# CC1101 sub-1GHz radio (SPI model)

`SPI.CC1101` is a register-accurate model of the TI CC1101 radio for the
emulated ESP32-C3. It gives the firmware's CC1101 driver a functional SPI slave
to talk to without hardware: SPI framing, the full register map, the
command-strobe state machine, and the GDO0/GDO2 GPIO output lines.

It does **not** model the RF data path, modulation, or timing — that is the
later shared "433 MHz air medium" wave. This wave is register + strobe + GPIO
accurate only.

Source: `peripherals/cc1101/CC1101.cs`. It implements `ISPIPeripheral`
(`Transmit`/`FinishTransmission`/`Reset`) and `INumberedGPIOOutput` (the GDO
lines), mirroring `peripherals/spi2/SPILoopbackTester.cs` and Renode's own
`Wireless.CC2520`.

## Attaching in a .repl

The SPI2 master (`SPI.ESP32C3_SPI2 @ sysbus 0x60024000`) is a
`NullRegistrationPointPeripheralContainer<ISPIPeripheral>` — it holds a single
slave. Attach the radio as its child and wire the GDO outputs to GPIO input
pins:

```
radio: SPI.CC1101 @ spi2
    0 -> gpio@4          // GDO0 -> GPIO pin 4
    2 -> gpio@5          // GDO2 -> GPIO pin 5
```

Include `CC1101.cs` (via a setup `.resc` `include`, or `Execute Command include
@...`) before `LoadPlatformDescription`. The class must live in namespace
`Antmicro.Renode.Peripherals.SPI` — Renode's `.repl` resolver only searches
`Antmicro.Renode.Peripherals.*`, so the short form is `SPI.CC1101`.

Numbered GPIO outputs: `0` = GDO0, `1` = GDO1, `2` = GDO2.

## SPI framing

Every transaction starts with a header byte:

| bit  | meaning                          |
|------|----------------------------------|
| 7    | R/W (1 = read, 0 = write)        |
| 6    | BURST (auto-increment / FIFO)    |
| 5:0  | address                          |

The header byte always returns the **STATUS byte** on MISO:

| bits | meaning                                                    |
|------|------------------------------------------------------------|
| 7    | CHIP_RDYn (always 0 = ready in this model)                 |
| 6:4  | STATE (IDLE=0, RX=1, TX=2, FSTXON=3)                       |
| 3:0  | FIFO bytes available (RX count on read, TX free on write)  |

Address decoding:

- `0x00–0x2E` — config registers, single or burst (auto-increment) read/write.
  Reset defaults are the datasheet power-on values; writes read back.
- `0x30–0x3D` — the BURST bit disambiguates:
  - BURST = 0 → **command strobe** (single header byte).
  - BURST = 1 → **status register** read (read-only; requires the burst bit).
- `0x3E` — PATABLE, 8-byte read/write (burst wraps at 8).
- `0x3F` — FIFO: write = TX FIFO, read = RX FIFO.

`Transmit(b)` is called once per byte in order (header, then data); its return
is the MISO byte the ESP reads. `FinishTransmission()` (CS deassert) resets the
per-transaction byte position.

## Modeled register values

- **PARTNUM** (status `0x30`) = `0x00`
- **VERSION** (status `0x31`) = `0x14`
- **MARCSTATE** (status `0x35`) tracks strobes:
  - after SRES / SIDLE → `0x01` (IDLE)
  - after SRX → `0x0D` (RX)
  - after STX → `0x13` (TX)
  - after SFSTXON → `0x12` (FSTXON), after SPWD → `0x00` (SLEEP)
- **TXBYTES** (`0x3A`) / **RXBYTES** (`0x3B`) reflect the modeled FIFO counts.
- **RSSI** (`0x34`) returns a fixed plausible raw value (`0x80`).
- Other status regs return `0x00`.

Command strobes: SRES `0x30`, SFSTXON `0x31`, SXOFF `0x32`, SCAL `0x33`,
SRX `0x34`, STX `0x35`, SIDLE `0x36`, SWOR `0x38`, SPWD `0x39`, SFRX `0x3A`,
SFTX `0x3B`, SWORRST `0x3C`, SNOP `0x3D`.

## GDO output lines

Only the **constant-level** GDO settings are modeled — enough for the firmware's
GDO pin-identify logic:

- `IOCFGx` GDOx_CFG (bits 5:0) = `0x2F` ("HW to 0") drives the line to 0.
- `IOCFGx` GDOx_INV (bit 6) inverts it → 1.
- `0x2E` (three-state / high-Z) and unmodeled data modes park the line low
  (INV still flips it).

Writing `IOCFG0`/`IOCFG1`/`IOCFG2` updates the corresponding GDO line
immediately, as does a strobe/reset. A real serial-data / OOK GDO waveform is a
later air-medium wave.

## Test

`peripherals/cc1101/test.robot` boots `peripherals/cc1101/firmware`
(`test_cc1101.c`), which drives the model over the ESP-IDF `spi_master` driver
the way the real CC1101 driver does, and asserts 10 `[CC1101]` checks:
identity (PARTNUM/VERSION), config write+readback (PKTLEN/IOCFG2), MARCSTATE
after SRX/SIDLE, and independent constant-level GDO0/GDO2 levels read back
through GPIO4/GPIO5.

```bash
source ~/esp/esp-idf/export.sh
idf.py -C peripherals/cc1101/firmware set-target esp32c3
idf.py -C peripherals/cc1101/firmware build

renode-test \
  --variable "BASE:$PWD" \
  --variable "ROM_ELF:$HOME/esp/esp-rom-elfs/esp32c3_rev3_rom.elf" \
  peripherals/cc1101/test.robot
```
